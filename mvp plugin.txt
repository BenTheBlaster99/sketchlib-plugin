3. PLUGIN — WHAT WAS BUILT (PHASES)
================================================================================

PHASE 1 — Ruby skeleton ✅
  • sketchlib.rb registers SketchupExtension
  • sketchlib/main.rb — UI::HtmlDialog, Extensions → SketchLib menu
  • sketchlib/bridge.rb — get_hardware_id (Win / Mac / Linux fallback)
  • Ruby callbacks: getHardwareId, saveToken, getSavedToken, clearToken,
    insertModel
  • load_sketchlib.rb MUST live in Plugins ROOT (SketchUp ignores .rb in subdirs)

PHASE 2 — Auth UI ✅
  • React 18 + Vite, built to ui/dist/
  • Login: POST /auth/login { email, password, hardware_id }
  • Token stored via Sketchup.write_default('SketchLib', 'auth_token')
  • API URL baked at build: VITE_API_URL in ui/.env → npm run build
  • Backend CORS: allowed_origins includes 'null' (HtmlDialog file://)

PHASE 3 — Library UI ✅
  • Library.jsx — category tabs, search, 2-column grid
  • ModelCard.jsx — thumbnail, metadata, Insert button
  • access.js — beta / active subscription = full access; pack-only = 🔒 tabs
  • GET /auth/me → pack_category_ids for gating

PHASE 4 — Insert ✅ (verified on sister's PC)
  • POST /models/{id}/download → presigned R2 URL
  • bridge.rb download_and_insert: Net::HTTP → Tempfile .skp → definitions.load
    → add_instance → unlink temp (never definitions.load(URL) — R2 query strings
    break SketchUp)
  • Test: test-cube.skp uploaded via presign → Filament "Test Cube" → Insert OK

PHASE 5 — NOT DONE (pre-deploy polish)
  • Production VITE_API_URL rebuild
  • UX polish (loading skeletons, better errors, refresh button)
  • Extension Warehouse / RBZ packaging for distribution
  • Optional: model update badges, local cache, offline mode

        ├── app.js            # ~148 KB — Ruby reads & injects into HTML

Ruby main.rb validates app.js >= 100 KB; shows messagebox if missing/stale.

DO NOT ship old ui/dist/index.html (~104 KB) — deprecated, causes SyntaxError.

UI load path: set_html(build_ui_html) — not set_file — avoids file:// asset bugs.

7. PLUGIN API CONTRACT
================================================================================

Base: VITE_API_URL (built into app.js), e.g. http://192.168.217.133:8000/api

  POST   /auth/login
         Body: { email, password, hardware_id }
         Returns: { user, token }  — token name "plugin" on server
         403 if device_mismatch (account bound to other PC)

  GET    /auth/me              [Bearer plugin token]
         Returns: { user, pack_category_ids }

  POST   /auth/logout          [Bearer]

  GET    /categories         (public)

  GET    /categories/{slug}/models   [Bearer]
         Returns: { category, models[] }  — thumbnail_url may be null

  POST   /models/{id}/download       [Bearer]
         Returns: { download_url }  — R2 presigned GET, ~10 min

Plugin does NOT call: register, subscriptions checkout, admin routes, packs purchase
(those are web-only; subscribe on site, use plugin to consume library).

12. PRODUCTION DEPLOY RUNBOOK (STEP-BY-STEP)
================================================================================

ORDER: Backend first → verify API → Next.js → rebuild plugin → test → Sarah content

─── A) LARAVEL (API + FILAMENT) ───

  1. Choose host: Railway, Forge+VPS, Fly.io, Laravel Cloud, etc.
  2. Provision managed MySQL; import or migrate fresh DB
  3. Set production .env:
       APP_URL=https://api.yourdomain.com
       FRONTEND_URL=https://yourdomain.com
       SANCTUM_STATEFUL_DOMAINS=yourdomain.com
       DB_* (production credentials)
       R2_* (same bucket or separate prod bucket)
       FILESYSTEM_DISK=r2
       SESSION_SECURE_COOKIE=true
       APP_ENV=production
       APP_DEBUG=false
  4. Deploy code; run:
       php artisan migrate --force
       php artisan config:cache
       php artisan route:cache
  5. HTTPS only; point api.yourdomain.com to app
  6. Smoke test:
       GET https://api.yourdomain.com/api/categories
       Filament https://api.yourdomain.com/admin
       Postman presign + PUT on prod (admin token)
  7. Create Sarah's admin user (is_admin=true) in Filament
  8. Optional: php artisan queue:work (Resend emails)

─── B) NEXT.JS STOREFRONT ───

  1. Host on Vercel or same VPS (Node)
  2. Env:
       NEXT_PUBLIC_API_URL=https://api.yourdomain.com/api
       NEXT_PUBLIC_PAYMENT_ACCOUNT=<real BaridiMob when ready>
  3. Deploy; npm run build in CI
  4. Migrate to Sanctum SPA cookies if desired (backend CORS already supports
     credentials; remove js-cookie Bearer pattern from web — see web handoff)
  5. Smoke: register, login, browse, checkout pending, Filament approve, download

─── C) SKETCHUP PLUGIN ───

  1. On build machine:
       cd sketchlib-plugin/ui
       VITE_API_URL=https://api.yourdomain.com/api npm run build
  2. Package for users:
       • load_sketchlib.rb
       • sketchlib-plugin/ (full folder with dist/app.js ~148KB)
       • Optional: zip as sketchlib-plugin-v1.0.0.zip with README install steps
  3. Distribute: download link, GitHub release, or email to beta testers
  4. User install: copy to Plugins folder, restart SketchUp
  5. Smoke on Windows/Mac:
       Login with production account
       Browse category
       Insert one model
  6. Extension Warehouse (later): package .rbz, Trimble review process

─── D) CORS / SECURITY CHECKLIST ───

  [ ] cors.php includes production frontend URL
  [ ] 'null' origin kept for SketchUp HtmlDialog OR test prod plugin still works
  [ ] R2 bucket private; only presigned access
  [ ] Plugin tokens revocable; hardware_id reset documented for support
  [ ] Rate limiting on /auth/login if exposed publicly

─── E) CONTENT (SARAH) — AFTER PROD INFRA LIVE ───

  1. Naming convention for file_key: models/{category_slug}/{uuid}-{slug}.skp
  2. Upload via Filament or presign workflow
  3. Thumbnails recommended for browse UX (not required for insert)
  4. First batch 5–10 models per category; verify web download + plugin insert
  5. POST /admin/notify/new-models when Resend ready (web email, not plugin yet)

─── F) POST-DEPLOY VERIFICATION MATRIX ───

  | Flow                         | Where to test        |
  |------------------------------|----------------------|
  | Register / login web         | yourdomain.com       |
  | Subscribe / pack checkout    | web + Filament approve |
  | Browse / download .skp web   | dashboard            |
  | Plugin login                 | SketchUp + prod API  |
  | Plugin insert                | SketchUp + prod R2   |
  | Device lock                  | second PC → 403      |
  | Admin upload new model       | Filament → plugin    |
