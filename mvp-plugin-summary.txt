1. WHAT THE PLUGIN IS
================================================================================

Ruby extension + HtmlDialog panel inside SketchUp. Users log in with the same
Laravel API as the website. Plugin login sends hardware_id (one PC per account).
Browse categories → download .skp via presigned URL → Ruby inserts into the
active SketchUp model.

Stack:
  • Ruby: sketchlib.rb, sketchlib/main.rb, sketchlib/bridge.rb
  • UI: React 18 + Vite → single inlined index.html for SketchUp file://
  • Loader: load_sketchlib.rb must sit in Plugins ROOT (not only subfolder)

6. MODELS & CONTENT — RELEVANT FOR "UPDATING MODELS" DISCUSSION
================================================================================

Where models live today:
  • DB: sketchup_models (metadata, category, file_key, thumbnail, publish flag)
  • Files: Cloudflare R2 (.skp + thumbnails) — presigned URLs on download
  • Admin: Filament on Laravel — upload, publish, categories

What the plugin does NOT have yet:
  • No "check for updates" or version sync in the plugin
  • No cache of .skp files locally — each insert = fresh download
  • No push notification when admin drops new models
  • Plugin always reads live API lists (GET categories / models) — new published
    models appear on next panel open or category refresh (no auto-refresh timer)

If you add "model updates" you might touch:
  • Backend: model version field, updated_at, notify endpoint (email exists:
    POST /admin/notify/new-models — not wired to plugin)
  • Plugin: poll or manual refresh, show "new" badge, re-download on insert
  • R2: same presigned download flow; file_key change = new URL

Hardware lock unchanged: one plugin device per user (hardware_id on users table).
