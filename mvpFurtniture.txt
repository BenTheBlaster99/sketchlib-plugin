1. WHAT THIS FRONTEND IS
================================================================================

SketchLib web is the customer-facing Next.js storefront for a SketchUp 3D
furniture model library (.skp files). It connects to the Laravel REST API
(Sanctum Bearer tokens) and does NOT include an admin UI — day-to-day admin
work lives in Filament at http://localhost:8000/admin on the backend repo.

Business flows implemented on the web:

  • Register / login / logout
  • Browse pricing plans (public)
  • Subscribe via manual payment (BaridiMob / CCP reference — placeholder account)
  • Buy a single category pack via manual payment
  • Browse categories in the library (access-gated)
  • View models in a category + download .skp via presigned R2 URL
  • Admin approves payments in Filament → user gets access on next page load

What is intentionally OUT of scope for this repo:

  • Next.js /admin pages (Filament handles subscriptions, packs, models, users)
  • SketchUp plugin (separate project; same API, hardware_id login)
  • Real BaridiMob / Algerian Post payment API (manual transfer + admin approval for now)
  • Production deploy (both repos still local-dev oriented)

5. ROUTE PROTECTION (middleware.ts)
================================================================================

  /dashboard/*   Requires auth_token cookie → else redirect /auth/login?next=...
  /checkout/*    Same as dashboard
  /auth/*        If already logged in → redirect /dashboard (or ?next= target)

  NOT protected: /, /pricing (public)

  NOT in this app: /admin/* (Filament on Laravel)


================================================================================
6. AUTH FLOW
================================================================================

  Token storage : js-cookie key auth_token, 30-day expiry
  API auth      : Authorization: Bearer {token} on every axios request
  Bootstrap     : On mount, if cookie exists → GET /auth/me → user + packCategoryIds
  401 handling  : Clear cookie, redirect to /auth/login
  Hydration     : isLoading=true until client mount completes (server/client HTML match)

  AuthContext exposes:
    user, token, packCategoryIds, isLoading, login(), logout(), refresh()

7. API ENDPOINTS USED (CLIENT ONLY)
================================================================================

Base: NEXT_PUBLIC_API_URL (default http://localhost:8000/api)

AUTH
  POST   /auth/register
  POST   /auth/login
  POST   /auth/logout          [Bearer]
  GET    /auth/me              [Bearer]  → user, pack_category_ids

PUBLIC
  GET    /categories
  GET    /plans

CLIENT [Bearer]
  GET    /categories/{slug}/models
  POST   /models/{id}/download     → { download_url } presigned R2
  GET    /subscriptions/current
  POST   /subscriptions              → payer_name, payment_ref, plan_id
  GET    /packs/purchased
  POST   /packs/{categoryId}         → payer_name, payment_ref

Admin API routes are NOT called from this frontend.
